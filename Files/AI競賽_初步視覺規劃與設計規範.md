## 1. 設計定位

### 1.1 核心概念

以「國防科技 × AI 創新 × 任務導向」為主軸，建立一個具有官方可信度、科技前瞻性與競賽行動感的活動網站。

關鍵印象：

- 穩健：符合國防相關活動的正式與可信任感。
- 前瞻：讓 AI、資料、決策支援與技術創新成為視覺語言。
- 任務感：清楚引導使用者了解活動、掌握時程並完成報名。
- 開放：避免過度軍事化，不使用武器、戰爭或迷彩作為主要視覺。

### 1.2 一句話方向

> 以深色指揮中心為基底，結合資料網格、雷達座標與高亮訊號，呈現一場面向未來國防應用的 AI 創新任務。

### 1.3 不採用的方向

- 不使用整頁迷彩、槍械、爆炸、戰場照片等直白軍事素材。
- 不做成密集儀表板或純科技產品 SaaS 介面。
- 不用大量霓虹漸層、故障藝術或過度賽博龐克效果，避免降低官方活動的可信度。
- 不讓裝飾線條、動畫或背景資訊流蓋過報名入口與重要時程。

## 3. 視覺語言

### 3.1 主視覺元素

- **深色基底**：建立指揮中心、任務中樞與官方可信度。
- **座標／網格**：象徵精準、系統、空間定位與資料結構。
- **雷達弧線**：作為局部裝飾，不作為主要資訊載體。
- **資料節點與連線**：表現 AI、跨域協作與決策支援。
- **高亮訊號**：用青綠或琥珀色標示重要日期、報名狀態與行動按鈕。
- **斜切或切角**：少量使用在 Hero、標籤與分隔線，增加任務感；避免每個元件都切角。

### 3.2 圖像方向

優先使用：

- 抽象化的 AI 資料網路、衛星／地形線稿、雷達掃描、無人系統輪廓。
- 真實活動照片：人物、討論、展示、成果發表；需有正式授權。
- 大面積低對比背景圖，確保標題與 CTA 可讀。

圖片處理原則：

- 圖片加 30–55% 深色遮罩，避免文字壓在高反差細節上。
- 主視覺使用 16:9 或 3:2 構圖，主體避開標題與按鈕區。
- 裝飾性圖像使用空的 `alt`；具有資訊功能的圖片需提供描述。
- Demo 階段可使用抽象圖形或暫代圖，正式上線前替換為授權素材。

### 4.1 色彩 Token

| Token | 色碼 | 用途 |
| --- | --- | --- |
| `--color-ink-950` | `#06131F` | 深色 Hero／頁尾背景 |
| `--color-ink-900` | `#0A1F31` | 深色區塊、導覽列 |
| `--color-ink-800` | `#12334C` | 卡片、表格與深色層次 |
| `--color-surface` | `#F4F8FA` | 主要淺色背景 |
| `--color-white` | `#FFFFFF` | 卡片與反白文字 |
| `--color-text` | `#102A43` | 主要內文 |
| `--color-text-muted` | `#526777` | 次要說明文字 |
| `--color-line` | `#D5E1E7` | 邊框、分隔線 |
| `--color-cyan` | `#42E0D0` | 科技高亮、焦點、進度 |
| `--color-blue` | `#2674A8` | 連結、次要按鈕、圖表 |
| `--color-amber` | `#F4B740` | 重要提醒、日期、注意事項 |
| `--color-success` | `#147D64` | 完成、通過、成功狀態 |
| `--color-danger` | `#B42318` | 錯誤、缺件、截止提醒 |

### 4.2 使用比例

- 深色主視覺／導覽：約 35–45%。
- 白色與淺色內容區：約 45–55%。
- 青綠、藍、琥珀高亮：合計不超過 10–15%。
- 青綠與琥珀不可同時大量使用；一個區塊只保留一個主要強調色。

### 4.3 對比與語意

- 一般文字需達 WCAG AA：至少 4.5:1。
- 大字與圖形文字至少 3:1。
- 不只靠顏色表示狀態，需搭配文字、圖示或圖案。
- `--color-cyan` 僅用於深色背景上的高亮，不用作淺色背景上的小字。
- 錯誤狀態同時顯示「錯誤／缺件／請重新上傳」等文字，不只顯示紅色。

## 5. 字體與排版

### 5.1 字體

```css
:root {
  --font-sans: system-ui, -apple-system, BlinkMacSystemFont,
    "Noto Sans TC", "PingFang TC", "Microsoft JhengHei", sans-serif;
  --font-mono: "SFMono-Regular", Consolas, "Liberation Mono", monospace;
}
```

- 中文以 `Noto Sans TC` 或系統黑體為主，保持清楚、正式、易讀。
- 英數標題可搭配等寬字體作小型資料標籤，不用等寬字體排整段中文。
- 不使用過度裝飾性的軍事 stencil 字體作為主要標題。

### 5.2 字級層級

| 層級 | Desktop | Mobile | 用途 |
| --- | --- | --- | --- |
| Display | `clamp(2.5rem, 5vw, 5.5rem)` | `2.5rem` | 首頁 Hero 主標 |
| H1 | `clamp(2rem, 3.5vw, 3.75rem)` | `2rem` | 內頁主標 |
| H2 | `clamp(1.5rem, 2.5vw, 2.5rem)` | `1.5rem` | 主要段落標題 |
| H3 | `1.25rem–1.5rem` | `1.25rem` | 卡片／小節標題 |
| Body | `1rem–1.125rem` | `1rem` | 主要內文 |
| Caption | `0.875rem` | `0.875rem` | 輔助說明、日期、標籤 |

排版原則：

- 每頁只使用一個 `h1`，標題階層不可跳級。
- 內文行高 1.6 左右；標題行高 1.15–1.25。
- 文字欄最大寬度約 65–75 字元，避免整行過長。
- 日期、編號、檔案大小使用等寬數字或 `tabular-nums`，方便掃讀。

## 6. 版型與間距

### 6.1 Layout

- 最大內容寬度：`1200px`。
- 主要容器：`width: min(100% - 2rem, 1200px)`。
- Desktop 以 12 欄 Grid 為基礎；Tablet 8 欄；Mobile 4 欄。
- Hero 可滿版，但內文與 CTA 必須落在內容容器內。
- 重要資訊優先靠近左側或內容起點，符合中文閱讀與快速掃讀習慣。

### 6.2 Spacing Scale

以 4px 為基本單位：

```css
:root {
  --space-1: 0.25rem;  /* 4px */
  --space-2: 0.5rem;   /* 8px */
  --space-3: 0.75rem;  /* 12px */
  --space-4: 1rem;     /* 16px */
  --space-6: 1.5rem;   /* 24px */
  --space-8: 2rem;     /* 32px */
  --space-12: 3rem;    /* 48px */
  --space-16: 4rem;    /* 64px */
  --space-24: 6rem;    /* 96px */
}
```

- 元件內距：16–24px。
- 卡片之間：16–24px。
- 區塊之間：64–96px，使用 `clamp()` 做流動調整。
- 不用陰影堆疊來區分所有區塊，優先使用背景色、邊框與留白。

### 6.3 圓角與邊框

- 大型容器：`16px`。
- 一般卡片／表單：`10–12px`。
- 按鈕／輸入框：`8px`。
- 狀態標籤：`999px`，只用於短標籤，不用於大型資訊卡。
- 邊框以 1px 細線為主；重要焦點可使用 2px。

## 7. 元件規範

### 7.1 導覽列

- Desktop：左側活動識別／Logo，右側主要頁面連結與「立即報名」CTA。
- Mobile：Logo、選單按鈕、固定的「報名」入口。
- 目前頁面使用明顯 active state，並加入 `aria-current="page"`。
- 導覽列可採深色固定樣式；滾動後可加半透明背景與細邊框。

### 7.2 Hero

- 左側放活動定位、主標、日期與 CTA；右側放抽象科技視覺或活動主圖。
- 主標最多 2–3 行，避免把所有資訊塞進主視覺。
- CTA 最多一個主按鈕、一個次按鈕。
- Hero 內需直接看見「活動是什麼」與「下一步去哪裡」。

### 7.3 按鈕

- Primary：青綠底＋深色字，或深藍底＋白字；依背景選擇。
- Secondary：透明／深色底搭配 1px 邊框。
- Danger：只用於刪除、取消上傳或不可逆操作。
- 最小觸控尺寸 44×44px；按鈕文字使用明確動詞，如「立即報名」「下載辦法」「查看時程」。
- Hover 與 keyboard focus 必須有同等可見回饋。

### 7.4 時程 Timeline

- Desktop 可用水平或左右交錯節點；Mobile 改為單欄垂直時間軸。
- 每個節點包含日期、階段名稱、簡短說明與狀態。
- 目前／下一階段用青綠高亮；已完成使用低飽和色；截止／提醒使用琥珀。
- 不把完整辦法文字塞進時間軸，詳細內容連往內頁。

### 7.5 資訊卡

- 卡片只承載一個主題：活動亮點、參賽資格、文件下載或流程步驟。
- 標題、短說明、行動連結三層即可。
- 卡片可使用 1px 邊框與輕微背景，不使用重陰影與大量漸層。

### 7.6 文件下載列

- 顯示文件名稱、格式、檔案大小與「下載」動作。
- 格式使用文字標籤，例如 `DOCX`、`PDF`，不可只用顏色區分。
- 下載連結需是原生 `<a>`，不要用可點擊的 `<div>`。

### 7.7 表單與檔案上傳（介面預覽）

- 每個欄位都要有可見 `<label>`，placeholder 不可取代 label。
- 必填欄位以文字或星號清楚標示，並提供錯誤訊息。
- 上傳區需顯示允許格式、單檔容量、檔案數量與目前進度。
- 上傳成功、缺件、格式錯誤、截止鎖定要有獨立狀態，搭配文字與圖示。
- 提供「儲存草稿」與「繼續編輯」概念；不要只提供一次性送出。

### 7.8 公告／成果列表

- 以日期、分類標籤、標題與摘要組成。
- 公告列表需能辨識未讀／置頂／重要通知。
- 活動花絮以大圖＋短標題呈現；影片可使用封面圖與播放按鈕。

## 8. 互動與動態

動態以「引導注意、回饋狀態、說明資料關係」為目的。

- Hero 背景網格可有非常慢的位移或呼吸效果。
- 滾動進場使用 200–400ms 的淡入／位移，避免整頁同時跳動。
- 按鈕、卡片、下載列有 150–220ms 的 hover／focus transition。
- 上傳進度可用原生 progress bar 或明確百分比。
- 所有動態都必須支援 `prefers-reduced-motion: reduce`，此時停用非必要動畫。
- 不使用閃爍、快速掃描或高頻率粒子效果。

## 9. 響應式規則

以內容斷點為準，不綁定特定裝置：

```css
/* Base: Mobile */
@media (min-width: 30rem)  { /* 寬度增加，調整單欄內容 */ }
@media (min-width: 48rem)  { /* Tablet，雙欄與 8 欄 Grid */ }
@media (min-width: 64rem)  { /* Desktop，完整導覽與 12 欄 Grid */ }
@media (min-width: 80rem)  { /* Wide，增加留白，不無限放大文字 */ }
```

- Mobile 首頁 Hero 改為單欄，圖片／抽象視覺移到標題下方或作背景。
- Desktop 導覽連結可完整顯示；Mobile 使用原生按鈕開啟選單。
- 時程、卡片、表格在 320px 寬度仍不可造成整頁水平捲動。
- 表格若資訊過寬，限制在獨立可捲動容器內，不讓整個頁面水平捲動。
- 所有按鈕與重要連結保持至少 44×44px 觸控尺寸。

## 10. 無障礙與內容規則

- `<html lang="zh-Hant">`。
- 每頁一個 `h1`，標題階層依序使用。
- 使用 `<header>`, `<nav>`, `<main>`, `<section>`, `<footer>` 等語意元素。
- 提供「跳至主要內容」連結。
- 所有互動元素可用鍵盤操作，focus ring 不可移除。
- 圖片需有正確 `alt`；純裝飾圖片使用空 `alt`。
- 表單錯誤要靠文字說明，並用 `aria-describedby` 關聯欄位與訊息。
- 動態狀態使用 `role="status"` 或 `aria-live="polite"` 告知使用者。
- 不使用「點此」「按這裡」作為單獨連結文字，改用「下載競賽辦法」「查看活動時程」。
- 中文內文避免全形大寫與過長段落；重要規則拆成條列與小標題。

## 11. 靜態 Demo 建議頁面順序

第一階段先完成以下 4 頁即可驗證視覺方向：

1. **首頁**：確認主視覺、色彩、導覽、CTA 與時程元件。
2. **活動介紹／競賽辦法**：確認長文、章節、下載列與表格呈現。
3. **報名資訊**：確認流程圖、文件下載、注意事項與登入入口。
4. **公告／成果**：確認列表、圖片、影片封面與空狀態。

系統畫面先以靜態預覽呈現：登入、報名進度、檔案上傳、送出成功。暫不實作帳號、資料庫、寄信或檔案儲存。

## 13. Demo 驗收重點

- 第一眼能辨識「國防科技／AI 競賽」而非一般科技產品網站。
- 使用者在首頁 5 秒內能找到活動定位、日期與報名入口。
- 桌機與手機皆可閱讀，沒有水平溢出或文字被背景吃掉的情況。
- 下載、報名、公告、時程等主要任務都有明確的連結或按鈕。
- 版面保留足夠留白，科技裝飾不干擾資訊閱讀。
- 所有互動元件都有 hover、focus、disabled／錯誤等基本狀態規劃。
- 尚未確認的活動資訊使用明確 placeholder，不以假資料冒充正式內容。
